# 搜狐自媒体热帖生成器 — 设计文档

> **状态：** 已确认，待实现  
> **目标：** 一个云端托管的网页工具，用户手动点击按钮生成原创短帖，复制后搬运到搜狐新闻发布。  
> **技术栈：** GitHub Pages（静态托管） + GitHub Actions（云端执行脚本） + Claude API（内容生成）

---

## 1. 项目概述

### 1.1 要解决的问题

用户运营搜狐自媒体账号，需要每天产出有营养的原创短内容（非转发+点评模式）。手动找选题、写内容耗时耗力，希望自动化生成后人工筛选搬运。

### 1.2 核心功能

- 网页上点击按钮，每次生成 **1 篇**短帖子
- 用户选择风格：**轻松闲聊**（默认）或 **一句话快讯**
- 每篇帖子附带一张**相关配图**（Unsplash/Pexels 免费图库）
- 帖子展示在网页列表，支持**一键复制**和**删除**
- 云端运行，电脑关机不影响使用
- 任何设备（手机/平板/电脑）均可访问
- **明确不在范围：** 视频配图（无可用的免费新闻视频源，版权风险高）

### 1.3 非功能需求

- 零成本运行（使用 GitHub 免费额度）
- 手动触发，不消耗则不产生 API 费用
- 无需本地安装任何软件（初始设置除外）
- Token 加密存储，不暴露在代码中

## 2. 内容规范

| 要求 | 标准 |
|------|------|
| **篇幅** | 每篇 200 字以内 |
| **主风格** | 轻松闲聊型（C 类），像跟朋友聊天，口语化、自然 |
| **辅风格** | 一句话快讯（A 类），纯事实陈述 |
| **调性** | 有营养、不标题党、不博眼球 |
| **配图** | 每篇附带一张相关图片链接，AI 搜索免费图库匹配 |
| **话题** | 不限领域——科技、社会、财经、文娱，根据当日热点灵活选取 |
| **形式** | 独立原创短文，非"转发+点评"模式 |
| **签名** | 生成提示中显示"江 正在为你写稿 ✍️" |

### 2.1 风格示例

**轻松闲聊（C 类）：**
> "今天看到比亚迪固态电池的新闻，突然觉得我去年买的电车可能要贬值了😂 不过技术进步总是好事，早买早享受嘛～"

**一句话快讯（A 类）：**
> "比亚迪宣布全固态电池量产，续航突破1000公里，售价有望下探至15万区间。"

## 3. 架构设计

### 3.1 系统架构

```
┌──────────────────────────────────────────────────┐
│              GitHub 云端                           │
│                                                    │
│  ┌──────────────────────────────┐                 │
│  │   GitHub Pages (静态网站)     │                 │
│  │   index.html + style.css     │                 │
│  │   + script.js                │                 │
│  │   从 data/posts.json 读取    │                 │
│  └──────────┬───────────────────┘                 │
│             │ 用户点按钮 → 调 GitHub API           │
│             ▼                                      │
│  ┌──────────────────────────────┐                 │
│  │   GitHub Actions              │                 │
│  │   generate.yml                │                 │
│  │   workflow_dispatch 触发      │                 │
│  │   → scripts/generate.py      │                 │
│  │   → 调 Claude API 生成1篇    │                 │
│  │   → 追加到 data/posts.json   │                 │
│  │   → git commit & push        │                 │
│  └──────────────────────────────┘                 │
│                                                    │
└──────────────────────────────────────────────────┘
```

### 3.2 文件结构

```
sohuxw/
├── .github/workflows/
│   └── generate.yml          # Actions 工作流定义
├── scripts/
│   └── generate.py            # 内容生成脚本
├── data/
│   └── posts.json             # 帖子数据存储
├── index.html                 # 前端页面
├── style.css                  # 样式
├── script.js                  # 前端交互逻辑
└── README.md                  # 仓库说明
```

### 3.3 组件职责

| 组件 | 职责 | 接口 |
|------|------|------|
| `index.html` | 页面结构，帖子列表容器，控制栏 | DOM 结构 |
| `style.css` | 响应式布局，卡片样式，按钮动画 | CSS 类 |
| `script.js` | 触发生成、轮询状态、渲染列表、复制/删除 | 读 `data/posts.json`，调 GitHub API |
| `generate.py` | 抓当日热点，调 Claude API 生成帖子，写 JSON | 命令行参数 `--style` |
| `generate.yml` | 定义 Actions 触发条件和运行环境 | `workflow_dispatch` + inputs |
| `posts.json` | 帖子数组，最新在前 | JSON 文件 |

### 3.4 数据流

```
用户点「生成一篇」
  → script.js 调 GitHub REST API (workflow_dispatch)
  → GitHub Actions 启动
  → scripts/generate.py 执行
      ├─ 组装 prompt（含风格参数 + 日期）
      ├─ 调用 Claude API 生成文字 + 输出图片搜索关键词
      ├─ 用关键词调 Unsplash/Pexels API 获取配图链接
      ├─ 解析文字 + 图片链接
      └─ 读取 data/posts.json → 追加新帖 → 写回
  → Actions 自动 git commit & push
  → GitHub Pages 检测到更新 → 重新部署
  → 网页轮询发现 JSON 变化 → 自动刷新列表
```

### 4.2 交互行为

| 操作 | 行为 | 反馈 |
|------|------|------|
| 点「生成一篇」 | 调 GitHub API 触发 Actions | 按钮变灰显示"生成中..."，禁用 |
| 生成进行中 | — | 下方显示"江 正在为你写稿 ✍️" |
| 生成完成 | 轮询检测 JSON 更新 | 自动刷新列表，新帖出现在顶部 |
| 鼠标滑过卡片 | — | 卡片微微上浮，显示阴影 |
| 点「复制」 | `navigator.clipboard.writeText()` | 按钮变"✅ 已复制"，1 秒后恢复 |
| 点「删除」 | 弹确认框"确认删除这条帖子吗？" | 确认后从列表移除，ID 存入 localStorage，该设备上不再显示 |
| 切换风格 | 选中风格选项 | 下次生成使用所选风格 |
| 页面加载 | fetch `posts.json` | 渲染现有帖子列表 |

### 4.3 响应式

- 桌面端：最大宽度 640px 居中
- 手机端：全宽，卡片自适应

### 4.4 错误状态

| 情况 | 处理 |
|------|------|
| 生成中再次点击 | 按钮已禁用，不可重复点击 |
| API 生成失败 | 红色横幅提示"生成失败，请稍后重试" |
| 网络超时（30s） | 提示"响应超时，请重试" |
| JSON 文件为空 | 显示"暂无帖子，点击上方按钮生成第一条吧~" |
| 页面加载失败 | 显示"内容加载中..."，5 秒后提示手动刷新 |
| clipboard API 不可用 | 选中文字，提示"请手动 Ctrl+C 复制" |

## 5. 数据格式

### 5.1 posts.json

```json
[
  {
    "id": "20260609-143200-a1b2c3",
    "content": "今天刷到一条新闻...",
    "style": "chatty",
    "image_url": "https://images.unsplash.com/photo-...",
    "image_credit": "Photo by xxx / Unsplash",
    "created_at": "2026-06-09T14:32:00+08:00"
  }
]
```

- `id`: 唯一标识，格式 `YYYYMMDD-HHMMSS-随机6位`
- `content`: 帖子正文，纯文本
- `style`: `"chatty"`（闲聊）或 `"newsflash"`（快讯）
- `image_url`: 配图链接，来自 Unsplash 或 Pexels 免费图库
- `image_credit`: 图片来源署名（图库要求）
- `created_at`: ISO 8601 带时区
- 数组按 `created_at` 倒序（最新的在前）
- 文件大小上限：数组保留最近 200 条，超出时掉尾
- 删除为客户端操作（localStorage 存已删 ID），不修改服务端 JSON。换设备/清缓存后已删帖会恢复可见

### 5.2 GitHub Actions 触发参数

```yaml
workflow_dispatch:
  inputs:
    style:
      description: '帖子风格'
      required: true
      type: choice
      options:
        - chatty      # 轻松闲聊
        - newsflash   # 一句话快讯
```

## 6. Claude API 配置

- **模型：** Claude Haiku（速度快、成本低，适合短文本生成）
- **System Prompt 要点：** 身份设定（搜狐自媒体作者）、风格约束、篇幅限制、话题来源、杜绝标题党
- **Token 预估：** 每次生成约 500-1500 input + 200-300 output ≈ 1700-2500 tokens
- **API Key：** 存储在 GitHub Secrets → `ANTHROPIC_API_KEY`

## 7. 图片来源

- **图库：** Unsplash API（免费，无需 API Key，速率限制 50 次/小时）为主，Pexels API（免费，需注册 Key，速率限制 200 次/小时）为备选
- **搜索关键词：** Claude 在生成文字的同时输出 1-3 个英文图片搜索关键词
- **选图逻辑：** 用关键词搜 Unsplash，取第一张相关度最高的结果；Unsplash 无结果时降级到 Pexels；Pexels 也无结果时标记 `image_url: null`
- **署名要求：** Unsplash 和 Pexels 都要求署名，展示在图下方小字（如"Photo by xxx / Unsplash"）
- **图片格式：** 直接使用图库提供的 CDN 链接，不下载存储

## 8. 安全

| 项目 | 措施 |
|------|------|
| API Key | 存 GitHub Secrets，加密，代码中不可见 |
| 网页安全 | GitHub Pages 默认 HTTPS |
| 代码安全 | 仓库公开但无敏感信息，Actions 日志不打印 prompt |
| 用户操作 | 纯静态页面，无后端、无数据库、无用户系统 |

---

## 9. 限制和边界

- **不在计划内：** 用户登录、历史搜索、数据统计、AI 以外的内容源、自动发布到搜狐
- **免费额度：** GitHub Actions 2000 分钟/月（每次生成用 <1 分钟，正常使用不会超）
- **响应延迟：** 从点按钮到帖子出现约 15-60 秒（Actions 启动 + 生成 + Pages 部署）

---

## 10. 风险

| 风险 | 可能 | 缓解 |
|------|------|------|
| Anthropic API 服务中断 | 极低 | 提示用户稍后重试 |
| GitHub Actions 短暂不可用 | 极低 | 同上 |
| 热点信息不准确 | 低 | Prompt 要求基于广泛认知，非即时新闻 |
| 内容重复 | 中 | Prompt 要求多样化视角，必要时用户手动删除 |
